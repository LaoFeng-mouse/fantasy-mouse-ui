# Fantasy Mouse UI benchmark cases

The benchmark manifest defines four Strict cases, in this exact order:

1. [`signal-harbor`](./signal-harbor/) — SaaS dashboard
2. [`fieldnote-festival`](./fieldnote-festival/) — website
3. [`grid-forward-2030`](./grid-forward-2030/) — presentation
4. [`archive-lantern`](./archive-lantern/) — desktop

These case directories begin as metadata-only benchmark contracts. A case is pending until its editable source, runnable output, real-target exercise, screenshots, visual comparison, accessibility checks, and evidence have actually been produced and accepted. Pending metadata must not be read as proof that a case was generated, tested, run, rendered, visually checked, or accepted. Use the repository validator's `--allow-pending` option while this truthful pending state is intentional; the acceptance validator must continue to fail until every required gate is supported by real evidence.
